# ADR-013: اعتماد Local WebUI كواجهة مستخدم رسومية للاستوديو المحلي (FastAPI + HTML5/CSS/JS)

**الحالة:** معتمدة (Accepted)
**التاريخ:** 22 نوفمبر 2026
**السياق:** المرحلة الثالثة — Task 3.15a (Studio GUI & Project Management)
**المرجعية:** تحديث تطبيقي لـ ADR-001 و GOOGLE_FLOW_STUDIO_ROADMAP.md

---

## 1. السياق والمشكلة (Context & Problem Statement)

نصت القرارات المعمارية الأولية (ADR-001) على توفير واجهة مستخدم رسومية (Desktop GUI / Studio Interface) لإدارة القنوات والمشاريع والسيناريوهات والأصول دون الحاجة لاستخدام أوامر الطرفية دائماً، مع الحفاظ الصارم على قدرة النواة البرمجية على العمل بنمط مستقل تماماً دون واجهة (`Headless Core`).

عند تقييم خيارات بناء الواجهة على بيئة Windows وبيئات CI:
1. **أطر عمل سطح المكتب الثقيلة (Electron / Node.js):** تتطلب بيئة Node.js و npm وحزم ضخمة ومئات الميجابايت من التبعيات، مما يناقض متطلب المشروع في بقاء البيئة 100% بايثون خفيفة ومستقلة.
2. **أطر عمل GUI التقليدية في بايثون (Tkinter / PyQt / PySide):** تعاني من ضعف شديد ومشاكل تشويه في دعم اتجاه النصوص من اليمين لليسار (RTL) وتشكيل الحروف العربية المعقدة، فضلًا عن صعوبة اختبارها آلياً في بيئات CI غير المزودة بشاشة (Headless CI).
3. **أطر عمل الويب المحلية (FastAPI + Uvicorn + HTML5/CSS/Vanilla JS):**
   - 100% بايثون دون أي اعتمادية على Node.js أو npm.
   - دعم طبيعي ومثالي للغات متعددة والـ RTL والطباعة العربية عبر CSS وHTML5 القياسي.
   - سهولة الفحص والاختبار المؤتمت بنسبة 100% داخل CI عبر `TestClient` و `httpx`.
   - تعمل محلياً حصرياً على `127.0.0.1` مع فحص ديناميكي لمنفذ متاح، مما يوفر تجربة استوديو مكتبية سريعة عبر أي متصفح مثبت على النظام.

## 2. القرار المعماري (Architectural Decision)

تقرر اعتماد **Local WebUI** المرتكز على **FastAPI + Uvicorn + Jinja2 + HTML5/CSS/Vanilla JS** كتقنية رسمية لواجهة الاستوديو المحلية:

1. **العنوان المحلي والشبكة (Port 8050 & Localhost Only):**
   - تُقفل الواجهة حصرياً على العنوان المحلي الداخلي `127.0.0.1` (Localhost Only)، ويُحظر ربطها بـ `0.0.0.0` لمنع أي تعرض شبكي غير مقصود.
   - المنفذ الافتراضي المعتمد هو `8050` مع دعم متغير البيئة `STUDIO_WEB_PORT` (بقيمة افتراضية `8050`).
   - آلية استكشاف منافذ تلقائية تبدأ من المنفذ `8050` إلى `8090` وتبحث عن أول منفذ متاح تلقائياً على نظام Windows.
   - أولوية تحديد المنفذ:
     1. خيار `--port` عند تحديده صراحة في سطر الأوامر.
     2. متغير البيئة `STUDIO_WEB_PORT`.
     3. المنفذ الافتراضي `8050`.

2. **قاعدة عدم وجود Backend أو قاعدة بيانات موازية (Zero Parallel Backend):**
   - لا تُنشئ الواجهة أي قاعدة بيانات جديدة ولا تعيد كتابة أي منطق تشغيلي.
   - يحظر على مسارات الواجهة (`Routes`) استيراد `sqlite3` أو تنفيذ أي استعلام SQL مباشر.
   - جميع العمليات (القنوات، المشاريع، المشاهد، أطلس الشخصيات، حزم Flow، وإدارة الأصول) تمر حصرياً عبر طبقة الخدمات الرسمية (`Service Layer`: `ChannelService`, `ProjectService`, `SceneService`, `FlowPromptService`, `FlowInboundService`, `AssetService`, `StorageService`, `CharacterBibleService`).

3. **استقلالية النواة البرمجية (Headless Core):**
   - تظل النواة البرمجية (Core Engine) وكافة أدوات سطر الأوامر (CLI) قادرة على العمل والإنتاج والرندر والاختبار بشكل كامل 100% دون الحاجة لتشغيل خادم الواجهة.

---

## 3. النتائج الإيجابية والآثار (Consequences)

* **الإيجابيات:**
  - استقرار كامل على Windows وLinux CI.
  - دعم كامل للغتين العربية والإنجليزية مع محاذاة RTL مثالية.
  - اختبارات آلية بنسبة 100% دون الحاجة إلى Virtual Framebuffer (Xvfb) أو متصفحات ثقيلة.
  - الحفاظ على حجم المستودع خفيفاً ونظيفاً (Zero Node modules).
* **الالتزامات:**
  - إضافة التبعيات الخفيفة `fastapi`, `uvicorn`, `jinja2`, `python-multipart` إلى `requirements.txt` و `pyproject.toml`.
  - التحقق عبر اختبارات معمارية آلية من عدم وجود استدعاءات SQL مباشرة داخل حزمة `src/web/`.
